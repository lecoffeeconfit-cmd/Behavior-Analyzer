# Privacy and Chrome Web Store disclosure

Free analysis runs in the browser using packaged models. The extension inspects video elements only after the user invokes it. It does not collect general browsing history, use analytics, transmit local reports automatically, or send video to an AI API by default.

Saved reports contain the video title, a sanitized page URL (query string/fragment removed), timestamped captions, representative frames, facial/body landmark coordinates, audio measurements, and analysis notes. Uploaded-file reports also contain basic file metadata. This data can be sensitive. It stays in IndexedDB for the website origin or extension profile until the user deletes individual reports or clears the library, or browser storage is cleared. It is not encrypted by the application; the browser/operating-system profile controls device access. JSON/HTML exports are user-created local files.

Audio capture requires an explicit selection. Embedded audio uses Chrome's tab-sharing chooser; local uploads use the file's accessible audio track. No microphone is accessed. Audio is kept only in memory for the current report and is discarded on panel closure, report switching, or a new analysis. Shared-tab audio can include other sounds from that tab. A hard timeout stops recording.

Pro is optional. Clicking a cloud question/comparison sends the selected captions, report notes, and up to three representative frames per report to the configured secure backend, which forwards them to the administrator's AI provider. Clicking Pro transcription sends a WAV clip capped at 12 seconds. Both consume a bounded monthly allowance. Authentication sends account credentials to the configured authentication backend through HTTPS. Access tokens are kept in Chrome session storage restricted to trusted extension contexts, or the website tab's session storage. Shared AI keys, database credentials, and Stripe secrets remain server-side.

This document describes the code's data flows and is a starting point for a deployment-specific privacy policy, not a claim that a public policy or store listing is already published. Before Web Store submission, publish your policy, identify your configured backend/provider and their retention practices, complete the store's data-use disclosures, supply screenshots and support details, and test the exact final package. No DRM, authentication, CORS, or protected-video restrictions are bypassed.
